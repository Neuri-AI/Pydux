# Bindings de UI

El core de PyDux no conoce los widgets. Sus adaptadores programan las actualizaciones de UI en el event loop correcto del framework.

## `ReactiveBinding`

Utiliza `ReactiveBinding` para conectar un selector con un callback. Entrega inmediatamente el valor seleccionado actual y se detiene después de `dispose()`.

```python
from pydux.adapters.base import ReactiveBinding
from pydux.adapters.tkinter import TkinterBridge

binding = ReactiveBinding(
    store=store,
    selector=lambda state: state["user"]["name"],
    target=lambda name: label.config(text=name),
    bridge=TkinterBridge(root),
)

binding.dispose()
```

## `connect`

Utiliza `connect` para copiar un mapping de propiedades seleccionadas en una instancia de clase.

```python
from pydux.adapters.base import connect

@connect(
    store,
    map_state_to_props=lambda state: {
        "name": state["user"]["name"],
        "count": state["counter"]["value"],
    },
)
class Panel:
    def on_props_changed(self):
        print(self.name, self.count)
```

## Bridges del main thread

| Framework | Bridge | Mecanismo de programación |
| --- | --- | --- |
| Qt | `QtMainThreadBridge` | `QTimer.singleShot` |
| Tkinter | `TkinterBridge(widget)` | `widget.after_idle` |
| Kivy | `KivyBridge` | `Clock.schedule_once` |
| Independiente del framework/testing | `DirectThreadBridge` | Se ejecuta inmediatamente |

<Tip>
  Elige el bridge que corresponda con los widgets que se están actualizando. Un dispatch puede ocurrir fuera del loop de UI —especialmente dentro de un thunk— mientras que la modificación de widgets debe ejecutarse en el main thread del framework.
</Tip>
