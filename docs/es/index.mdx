# PyDux

PyDux es un contenedor de estado inspirado en Redux Toolkit para aplicaciones de escritorio en Python.
Proporciona a una aplicación una única fuente de verdad observable y una forma predecible de
cambiarla: despachar una acción, permitir que un reducer produzca el siguiente estado y actualizar
únicamente a los suscriptores cuyo valor seleccionado haya cambiado.

<Warning>
  PyDux se encuentra actualmente en alpha. Las APIs, los adaptadores de frameworks, el comportamiento de DevTools y
  los metadatos de empaquetado pueden cambiar entre releases.
</Warning>

## Qué proporciona PyDux

- **Slices** que mantienen juntos una sección del estado, la lógica del reducer y los creadores de acciones.
- **Suscripciones selectivas** mediante `store.select(...)` y selectores memoizados.
- **Thunks asíncronos** que modelan trabajo `pending`, `fulfilled` y `rejected`.
- **DevTools** con historial de acciones, time travel y un inspector local en el navegador.
- **Adaptadores de UI** para Qt, Tkinter, Kivy y Qyro sin una dependencia de GUI en el core.

## Cómo encaja con Qyro

| Herramienta | Responsabilidad |
| --- | --- |
| PyDux | Estado de la aplicación y transiciones de estado. |
| [Qyro Runtime](https://github.com/Neuri-AI/qyro) | Contexto de la aplicación, recursos, configuración y ciclo de vida de componentes. |
| [Qyro CLI](https://github.com/Neuri-AI/qyro-cli) | Creación de proyectos, desarrollo, builds, empaquetado y firma. |

PyDux puede utilizarse sin Qyro. Utiliza la integración con Qyro cuando tu aplicación
use componentes de Qyro y quieras suscripciones conscientes del ciclo de vida.

## El flujo de datos

```text
UI event → dispatch(action) → reducer updates state → selector changes → view updates
```

La UI no modifica directamente el estado compartido de la aplicación. Despacha acciones.
Esto hace que los cambios sean trazables, comprobables y fáciles de reproducir en DevTools.
