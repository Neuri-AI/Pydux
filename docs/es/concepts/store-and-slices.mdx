# Stores, slices y actions

PyDux mantiene el estado de la aplicación en un único store. El estado raíz normalmente es un diccionario con una key por cada slice.

```python
{
    "counter": {"value": 2},
    "user": {"name": "Ada"},
}
```

## Slices

Utiliza `create_slice(...)` para mantener juntos una sección del estado, sus reducers y sus creadores de actions generados. Un reducer recibe `(state, action)`. Puede modificar el draft proporcionado o devolver un estado de reemplazo.

```python
from pydux import create_slice

user_slice = create_slice(
    name="user",
    initial_state={"name": "Guest"},
    reducers={
        "set_name": lambda state, action: state.update(name=action.payload),
        "reset": lambda state, action: {"name": "Guest"},
    },
)
```

Los creadores de actions generados son `user_slice.actions.set_name(...)` y `user_slice.actions.reset()`. Sus tipos son `user/set_name` y `user/reset`.

## Combinación de slices

Pasa un mapping de nombres a slices o funciones reducer a `configure_store`.

```python
from pydux import configure_store

store = configure_store(
    {"counter": counter_slice, "user": user_slice},
    devtools=False,
)
```

Cada reducer de slice recibe únicamente su propia rama. Una action de un slice deja los demás slices sin cambios.

## Payloads y metadatos

Una action tiene un tipo, un payload opcional y metadatos opcionales. Los creadores de actions generados aceptan el payload como su primer argumento.

```python
action = user_slice.actions.set_name("Ada", meta={"source": "profile-form"})

assert action.type == "user/set_name"
assert action.payload == "Ada"
assert action.meta == {"source": "profile-form"}
```

## Actions externas con `extra_reducers`

Utiliza `extra_reducers` para actions que pertenezcan a otra funcionalidad, especialmente actions del ciclo de vida de async thunks.

```python
jobs_slice = create_slice(
    name="jobs",
    initial_state={"status": "idle", "result": None},
    reducers={},
    extra_reducers={
        "jobs/fetch/pending": lambda state, action: state.update(status="loading"),
        "jobs/fetch/fulfilled": lambda state, action: state.update(status="done", result=action.payload),
    },
)
```

<Tip>
  Mantén las funciones reducer centradas en las transiciones de estado. Coloca I/O, timers y llamadas de red en thunks o funciones de servicio, no en reducers.
</Tip>
